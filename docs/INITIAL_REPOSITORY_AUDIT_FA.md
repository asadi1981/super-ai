# گزارش ممیزی اولیه مخزن SUPER AI
تاریخ بررسی: 2026-11-06
مخزن: asadi1981/super-ai
شاخه بررسی‌شده: main
دامنه: فایل‌های متنی اصلی که از مخزن قابل دریافت بودند؛ فایل ZIP باینری هنوز بررسی محتوایی نشده است.

## 1. وضعیت واقعی کد موجود
| فایل | مشاهده | نتیجه |
|---|---|---|
| index.html | رابط فارسی RTL با بخش گفتگو، تولید محتوا، فایل، یادداشت و تنظیمات | رابط وب است، نه برنامه دسکتاپ/Android بومی |
| app.js | ذخیره گفتگو و یادداشت در localStorage و ارسال درخواست fetch به Worker | وابسته به مرورگر؛ اجرای محلی مدل در این فایل وجود ندارد |
| index.js | درگاه Cloudflare، مسیر health و api/chat، فراخوانی OpenRouter | موتور آنلاین است؛ اجرای مدل GGUF در Worker وجود ندارد |
| README-fa.md | صریحاً می‌گوید آفلاین فقط رابط/تاریخچه/یادداشت است و پاسخ زبانی آفلاین فعال نیست | ادعای آفلاین بودن مدل در نسخه فعلی مجاز نیست |
| wrangler.toml | تنظیمات Worker و مدل پیش‌فرض openrouter/free | پیکربندی استقرار آنلاین |
| styles.css | پوسته واکنش‌گرا و RTL | مختص رابط وب |
| manifest.webmanifest | مشخصات PWA با icons خالی | PWA بودن، اپ بومی یا runtime مدل نیست |
| sw.js | کش فایل‌های رابط و عدم کش API | آفلاین‌بودن پوسته را پشتیبانی می‌کند، نه تولید پاسخ مدل |
| SUPER_AI_Android_Engine_v2.zip | فایل باینری در مخزن دیده می‌شود، اما fetch متنی با خطای decode مواجه شد | محتوا، ساختار، امضا و قابل اجرا بودن آن هنوز تأیید نشده است |

## 2. یافته‌های مهم
1. مخزن فعلی یک نمونه وب/PWA با درگاه آنلاین است؛ هنوز SUPER AI CORE آفلاین و دو برنامه مستقل Assistant/Programmer در آن اثبات نشده‌اند.
2. app.js برای داده‌ها از localStorage استفاده می‌کند؛ این ذخیره‌سازی به مرورگر وابسته است و برای محصول قابل حمل دسکتاپ/Android جایگزین پایگاه داده/ذخیره‌ساز بومی نیست.
3. در index.js محدودسازی Origin وجود دارد، اما خود کد تصریحاً احراز هویت یا Rate Limit پیاده‌سازی نمی‌کند. CORS به‌تنهایی کنترل دسترسی محسوب نمی‌شود.
4. health فقط وضعیت زنده بودن Worker را می‌سنجد؛ موفقیت اتصال به ارائه‌دهنده مدل را ثابت نمی‌کند.
5. README راه‌اندازی و تنظیم دستی Secret را توضیح می‌دهد؛ وجود Secret یا موفقیت اتصال در حساب واقعی از روی کد قابل اثبات نیست.
6. ZIP اندروید یک قلم ناشناخته باقیمانده است و نباید بدون استخراج، اسکن و بررسی manifest/source/binary مبنای تصمیم فنی قرار گیرد.

## 3. ریسک‌های فنی/امنیتی
- endpoint عمومی Worker می‌تواند در معرض مصرف ناخواسته باشد؛ قبل از استفاده عمومی باید احراز هویت مناسب، سهمیه/Rate Limit، محدودیت اندازه درخواست، timeout و پایش هزینه افزوده شود.
- محدودسازی Origin مانع فراخوانی مستقیم غیرمرورگری یا جعل Origin در همه شرایط نیست.
- متن فایل‌های انتخابی در رابط وب فقط در textarea قرار می‌گیرد؛ عملیات فایل واقعی و اجرای کد در این نسخه وجود ندارد.
- قابلیت تشخیص گفتار به پشتیبانی مرورگر وابسته است و تضمین آفلاین ندارد.
- ZIP اندروید ممکن است نمونه، کد منبع یا binary قدیمی باشد؛ فعلاً وضعیت آن نامعلوم است.

## 4. اقدام اصلاحی پیشنهادی
- نسخه وب فعلی حفظ شود و فقط به‌عنوان prototype/اختیاری آنلاین برچسب بخورد.
- محصول مستقل از ابتدا بر اساس سند معماری هسته ساخته شود؛ نه با تبدیل شتاب‌زده PWA به ادعای اپ بومی.
- درگاه آنلاین بعداً به‌صورت provider اختیاری و با کنترل دسترسی مناسب نگهداری شود.
- فایل ZIP در مرحله ممیزی باینری جداگانه بررسی شود؛ تا آن زمان نه ادغام و نه اجرای خودکار.
- توسعه در شاخه design/core-architecture-v1 انجام شده است؛ شاخه main و نسخه منتشرشده در این مرحله تغییر نکرده‌اند.

## 5. محدودیت این ممیزی
این بررسی static review فایل‌های متنی قابل دریافت است؛ تست runtime، تست امنیت نفوذی، بررسی ZIP، بررسی Secretهای حساب Cloudflare و اجرای واقعی روی Windows 7 یا Android 11 انجام نشده است. بنابراین هیچ‌کدام از این موارد نباید به‌عنوان تست موفق گزارش شوند.
