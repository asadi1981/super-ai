# نقشه راه اجرایی SUPER AI
نسخه: 1.0 — 2026-11-06
مبنای طراحی: سند SUPER_AI_CORE_ARCHITECTURE_FA.md
وضعیت: برنامه پیشنهادی مرحله‌ای؛ هیچ مرحله‌ای به‌معنای تأیید اجرای تغییرات مخرب نیست.

## مرحله صفر — تثبیت و ممیزی دارایی‌های موجود
- تفکیک نمونه وب/Cloudflare فعلی از محصول آفلاین مستقل.
- ثبت فایل‌ها، نسخه‌ها، مجوزها، وابستگی‌ها و وضعیت واقعی هر قابلیت.
- نگهداری نسخه فعلی؛ توسعه در شاخه مستقل.
- خروجی: فهرست دارایی‌ها و ریسک‌ها. معیار عبور: مسیر ساخت محصول مستقل روشن باشد.

## مرحله یک — نمونه‌سازی runtime آفلاین Windows 7
- بررسی کامپایل/اجرای runtime GGUF روی Windows 7 SP1 x64 و CPU Pentium G2020.
- آزمون مدل qwen2.5-0.5b-instruct-q4_k_m.gguf با prompt فارسی و کدنویسی.
- اندازه‌گیری زمان بارگذاری، زمان تولید، RAM، خطا و پایداری.
- بررسی مدل‌های کوچک جایگزین فقط در صورت شکست معیارها.
- خروجی: گزارش آزمایش reproducible و انتخاب مستند runtime/model.
- مانع عبور: اگر runtime روی Windows 7 واقعی اجرا نشود، ساخت رابط کامل به تعویق می‌افتد.

## مرحله دو — هسته حداقلی قابل آزمون
پیاده‌سازی ماژولار:
- core/contracts.py: قرارداد ModelProvider و Tool.
- core/agent.py: چرخه درخواست و برنامه‌ریزی محدود.
- core/policy.py: مجوزها و سطح خطر.
- core/files.py: عملیات امن فایل و محدودیت مسیر.
- core/projects.py: workspace و metadata.
- core/audit.py: ثبت رویداد.
- core/backup.py: snapshot و rollback.
- providers/llama_cpp.py: adapter مدل محلی، پس از اثبات runtime.
- tests/: آزمون واحد و آزمون یکپارچه.
معیار عبور: آزمون‌ها، rollback و محدودیت مسیر موفق باشند.

## مرحله سه — SUPER AI Assistant دسکتاپ
- رابط فارسی Tkinter، راست‌چین، نمایش وضعیت مدل و خطا.
- گفتگو، حافظه محلی، مدیریت فایل و پروژه.
- بسته قابل حمل با مسیرهای نسبی و بدون نیاز به اینترنت.
- ساخت خروجی اجرایی فقط پس از تست روی دستگاه هدف.

## مرحله چهار — SUPER AI Programmer
- پنجره/محیط پروژه، مرور فایل‌ها، diff و ویرایش کنترل‌شده.
- اجرای Python در workspace، جمع‌آوری stdout/stderr و timeout.
- آزمون خودکار، گزارش خطا و پیشنهاد اصلاح.
- تغییرات مرحله‌ای با snapshot و تأیید پیش از اعمال روی فایل اصلی.

## مرحله پنج — نمونه مستقل Android 11
- اپ بومی Kotlin.
- آزمون بارگذاری مدل از فایل محلی با runtime بومی/JNI.
- سنجش RAM، دما، باتری و زمان پاسخ.
- سپس رابط گفتگو، مدیریت پروژه و انتقال بسته پروژه.
- قابلیت‌ها فقط پس از آزمون دستگاه واقعی فعال می‌شوند.

## مرحله شش — افزونه‌ها و اتصال برنامه‌ها
- تعریف manifest، نسخه API، مجوزها و sandbox برای افزونه‌ها.
- اولویت با API رسمی، CLI و فرمت فایل؛ UI automation آخرین گزینه.
- هر اتصال برنامه‌ای آزمون مستقل و مجوز حداقلی دارد.
- اتصال آنلاین فقط افزونه اختیاری و خاموش به‌صورت پیش‌فرض.

## مرحله هفت — انتشار و نگهداری
- بسته نصب/قابل حمل، checksum، نسخه و changelog.
- پشتیبان‌گیری و بازیابی آزمایش‌شده.
- بسته به‌روزرسانی آفلاین و امکان برگشت نسخه.
- راهنمای فارسی نصب، عیب‌یابی و امنیت.

## کارهای قابل انجام بدون دخالت کاربر
1. ممیزی فایل‌های مخزن و ثبت یافته‌ها.
2. تکمیل قراردادهای معماری و مدل داده.
3. تهیه تست‌کیس‌ها و معیارهای پذیرش.
4. طراحی نمونه‌های کوچک و آزمون‌های ایستا در محیط توسعه موجود.
5. ساخت شاخه‌های آزمایشی و ارائه تغییرات به‌صورت قابل بازبینی.
6. پرهیز از تغییر تنظیمات حساب، انتشار عمومی، خرید سرویس، ثبت Secret، حذف فایل یا ادغام به شاخه اصلی بدون اجازه.

## کارهایی که به دسترسی/تأیید کاربر وابسته‌اند
- اجرای binary روی رایانه Windows 7 واقعی و گوشی Android 11.
- دسترسی به فایل مدل محلی در دستگاه و سنجش عملکرد واقعی.
- تأیید مجوزها، کلیدها یا سرویس‌های بیرونی.
- نصب نرم‌افزار، تغییر تنظیمات سیستم یا انتشار نسخه عمومی.
- تصمیم نهایی برای ادغام شاخه توسعه در main.
